# 四川 pack_price 口径失真导致客群错分（2026-09-11）

- **日期**：2026-09-11
- **类型**：质态分析 / 模型模拟 / 数据质量
- **状态**：🟢 已确认（用户已处理：四川 subsidy_rate 改 0.9,1）

## 背景
- 0909 测试批次（淘顺 2026-08 订单，60,847 单 / 24 省）与 25 年模拟（通融历史）对比时，**四川省差异最大：-33.6pp**（模拟 44.9% → 实际 11.3%）
- 四川批次 **99.7% 落在 risk（高风险）分支**，而 25 年模拟输入里 risk 只占 0.4% → D/E 档占比 0.4% → 64.8%
- 用户提问「是不是错分」，触发本次核查

## 口径（关键）
- 数据源：`ods.ods_bl_credit_yzf_order_grant_apply`（通融 2025）/ `ods.ods_ts_credit_yzf_order_grant_apply`（淘顺 2026-08），StarRocks `ods` 库
- 客群切分模型：`tongrong_v1`，risk 判定 = `subsidy_rate ∈ [sr_left, sr_right]`
- **`subsidy_rate = (order_amt / repayments) / pack_price`**（clip 0~1），阈值来自 `sys_parameter.risk_strategy_info_config`

## 过程
1. **同特征回放**（用批次自身 `online_duration`/`operator_real` + 申请表金额跑本地模型）：整体分支一致率 69.4%，**四川 95.0%** → 四川的分配不是本地算错
2. **逐字段对比两源**：发现四川 `pack_price / order_amt` 中位比值 = **1.000（通融 25）vs 0.033（淘顺 26）**，其他 9 省两源一致（0.055~0.24）→ **只有四川异常**
3. **按月扫描（省×月）**：四川 `pack_price ≡ order_amt` 出现在 **2024-08 ~ 2026-04（21 个月、392,492 单）**，**2026-05 起修正**；其他 23 省无异常月
4. **影响推演**：25 年四川 subsidy ≡ (order_amt/36)/order_amt = **0.028 < 0.2** → 全判 normal → risk 分支仅 701 单（0.4%）→ **25 年四川基线与 risk 分支档位评级全部失真**；2026-05 修正后 subsidy = 0.833 → 95.2% 判 risk → 落 E/D 档（配置 2%/10%）→ 通过率骤降

## 结论
- **不是规则错、不是淘顺数据错，是四川·通融源 `pack_price` 长期被写成"合约总额"（=order_amt）**，导致补贴率计算恒为 1/36，risk/normal 判定完全失效
- 连带后果：25 年四川的"目标通过率 44.9%"和 risk 分支档位评级都建立在失真数据上
- 用户处置（2026-09-11 16:43:49，生产）：四川 `risk_strategy_info_config.subsidy_rate = 0.9,1` → 四川补贴率中位 0.833 < 0.9 → **全部落 normal（12 分支）**；本地模拟通过率 11.3% → **29.3%**

## 沉淀（可复用规则）
1. **同名产品在不同源/不同时期，字段可能被写成不同口径** → 做跨期/跨源对比前，先做**字段比值体检**（如 `pack_price/order_amt` 的省×月中位数），异常月一眼可见
2. **分类参数（subsidy/onlinetime 等）失真的表现是"某一档位占比突变"** → 见到"risk 占比突然 0.4%→99%"这种反转，先查输入字段口径，别急着调配置
3. **省份缺参 → 线上按「全国」行兜底**（已确认）；本地模型也必须一致，否则会出现 0.2~0.27 区间的系统性错分
4. 近月窗口做模拟，在网时长/运营商取**风控表**（`online_duration`/`operator_real`），不要用 DWS 竣工表（近月未竣工，匹配率仅 18~32%）
5. 本地 vs 批次比复审必须**同分母**（限批次初审通过子集），否则会出现 -20~-50pp 假差异
