## 0. 结论摘要（结论前置）

1. 外部数据（在网时长 / 在网状态+本异网 / 外部评分）是当前淘顺风控的两个支点：客群分流靠前两者，复审放行靠第三者。
2. 断供后不能靠填充或历史回填兜住：历史回填只覆盖已有数据的订单，而新办订单以新入网客群为主；缺失值中性化 ≈ -1，只会让分裂节点失效。
3. 可行出路：用内部可得特征为分裂变量重跑决策树，重建分流逻辑，使树在无外部数据前提下仍具区分度。
4. 本报告交付：影响评估 + 内部特征池盘点 + 样本/标签口径设计 + 建模与评估方案 + 下游改造清单 + 风险与执行计划。
5. 尚未做的一步：数据侧验证（特征覆盖率与单变量区分度实测）——需确认后执行。

## 1. 影响评估（结构层，已核对模型代码）

### 1.1 外部数据在风控链路的位置

| 数据 | 环节 | 作用 | 来源 |
|---|---|---|---|
| 在网时长 onlinetime / online_duration | 策略分流（决策树分裂变量） | 把客群切到不同分支 | 运营商侧（外部） |
| 在网状态（含本异网 operator_real） | 策略分流第一层 + 贷中/贷后预警 | 决策树第一层 is_bw；离网预警 | 第三方在网状态接口 |
| 外部评分（A卡/灵犀分 lxf） | 复审放行 | 外部评分 vs 分支 cutoff 分数线 | 第三方联合建模 RPC |

### 1.2 决策树对外部特征的依赖（已核对 risk_engine/model_registry/models/）

- jiangxi_v1（江西体系，多省共用，15 分支）：本网侧 7/15 个分支由 onlinetime<=4.5 决定（bw_d1_td4_fm_1、bw_d1_td4_m_2、bw_d1_tg4_fm_3、bw_d1_tg4_m_pn_4、bw_d1_tg4_m_pi_5、bw_g1_fm_td4_6、bw_g1_fm_tg4_7）；异网侧 7 支不吃在网时长，但第一层 is_bw 仍依赖外部运营商数据。
- hunan_v1（23 分支）：五维分裂含 onlinetime（bw_d1_g4_td4_4 / tg4_5）。
- gz_v1（贵州）：第一、二层分裂即 onlinetime<=3.5、<=0。
- tongrong_v1（通融）：onlinetime 阈值 + 老/新客判定 ou = onlinetime >= ot_std；注释已实证 operator/在网状态编码 bug 会导致评级错配（E→A 误杀 41、A→E 误放 18）。

### 1.3 断供的三个后果

1. 客群错配（最致命）：在网时长缺失 → 代码兜底 fillna(-1) 一律落「新客/低在网」侧；本异网缺失 → 第一层分裂直接断。优质老客被误杀，错分客群进错分支。
2. 分数线失效：外部评分缺失 → 复审无裁判，risk_cutoff 失去锚点，只能全拒（误杀）或全放（资损）。
3. 贷后信号丢失：运营商分期看「在网稳定性」（逾期本质=离网），在网状态接口断供 → 临近账期预警与离网预判失效，逾期后置暴露。

### 1.4 为什么「填充/回填」方案不成立（2026-10-08 用户纠正）

- 历史回填不可行：历史数据只覆盖「已有数据的订单」，而新办订单以新入网用户为主——恰恰是最缺在网时长、也最需要被区分的客群，回填补不到他们。
- 中性化 ≈ -1：缺失值改为中性/默认值，与 -1 效果相同，部分分裂节点同样失去区分效果。

> 结论：正确的方向不是「补数据」，而是换分裂变量——重新跑树，只用非外部数据的特征。

## 2. 内部特征池盘点（候选分裂变量，待圈定）

| 维度 | 候选特征 | 内部可得性 | 预期区分力 | 备注 |
|---|---|---|---|---|
| 用户 | age_interval、性别、custtype(00/01/06) | 可得（申请表/风控表） | 中 | 稳定可得 |
| 订单 | amt_interval / order_amt_yuan、pack_name(单卡/融合)、is_certify(补贴比例)、期数 | 可得 | 高 | 金额×补贴是本业务核心风险结构 |
| 时间 | is_weekend、下单时段 | 可得 | 低-中 | 补充变量 |
| 地理 | province_is_one(本地/异地)、city | 待确认来源 | 中 | province_is_one 是否为外部派生需核实 |
| 门店/渠道 | store_id、supplier_code、渠道等级(ods_ts_v3_order_store)、门店近 N 天进件量/历史质态 | 平台自有 | 高 | 最可能替代「在网时长」的区分力来源 |
| 内部行为 | 同身份证/手机号历史申请与履约、近 N 天多头申请、门店重复进件 | 需确认平台是否有现成特征 | 高 | 反欺诈维度，对纯新客仍有效 |

硬性剔除（外部依赖）：operator_real（本异网）、online_duration（在网时长）、lxf（A卡分）、model_id。

预判：old_new_customer 对新客无区分度，基本退位；区分力主要靠 金额×补贴结构 + 门店/渠道质量 + 内部行为频次。

## 3. 样本与标签口径设计

### 3.1 样本窗
- 取距当前 6~18 个月的淘顺实时授信订单：下限 6 个月保证表现期成熟，上限 18 个月避免客群/策略年代差异过大。
- 建议同时保留「申请时间」与「竣工时间」双标记，做时间边界验证。

### 3.2 剔除项（用户指定）
- 特殊订单：特批白名单通道（order_channel_id='特批白名单'、user_risk_level='E'）、保证金白名单、特殊审批件。
- 理由：特批直接放行不走策略，会扭曲 Vintage 与特征区分度评估（历史教训：特批曾使湖南贵州 Vintage 失真）。

### 3.3 标签定义（两套并列，评估时同时看）
- 口径 A：当期未还 step_num_repay_status = 2（FPD 类，成熟快）
- 口径 B：累计逾期 30+（add_thirty_overdue>=1，更接近终损）
- 表现期：与样本窗对齐，统一 ≥6 个月。

### 3.4 样本量与平衡
- 按省、按策略体系分层核对样本量；单省样本过小的省份合并或标注。

## 4. 建模与评估方案

### 4.1 特征筛选
- 先对候选特征逐个算单变量区分度（分箱逾期率 spread / IV），选出 4~6 个真正有区分力的进树，不做全量塞入。

### 4.2 分裂方式
- 自然划分：设定 max_depth、min_samples_leaf（如叶≥500 单）等约束，让树自然分箱，不预设分支数。
- 目标：本网/异网等外部维度移除后，用内部维度重建可解释的分层。

### 4.3 叶子质量门槛
- 每叶样本量下限；叶间逾期率 spread 下限；风险随层级单调（避免倒挂）。

### 4.4 评估指标
- 叶间逾期率 spread / lift、KS、单调性、稳定性（跨月/跨省 PSI）。
- 与旧树客群重合度、迁移成本。

### 4.5 流程要求
- 走平台 data.fetch + model_registry 注册/评估流程，不自己手写取数与分类器（既有铁律）。
- 禁止仅凭模拟分支质态配置通过率；须用生产实盘验证（模拟 vs 生产差异有前车之鉴）。

## 5. 下游改造清单（树变了必须同步重建）

1. strategy_id → risk_score_control 通过率配置映射重建。
2. risk_cutoff 分数线：外部评分没了，需建内部评分口径的 cutoff。
3. 旧→新分支迁移映射（否则历史配置、日报口径全断）。
4. 日报 / 监控 / 异动归因口径同步。
5. 配置推送走标准流程：plan → 改本地 → config_validate → config_push → 回读校验（含时间字段非 0000）。

## 6. 风险与不确定项

| 风险 | 说明 | 应对 |
|---|---|---|
| 新客区分度不足 | 新办订单以新客为主，内部特征区分力可能偏弱 | 引入门店/渠道/行为频次；spread 不达标的维度直接弃用 |
| 与旧版不可比 | 换分裂变量后通过率不可与外部数据版本直接比较 | 建立新基线，不与旧口径并列 |
| 模拟≠生产 | 模拟分支质态与线上不一致 | 调 PR 前必须生产实盘验证 |
| 体系混淆 | 线上可能跑 2511 而非 2608 | 动手前先查 ods_ts_order_white_list_control.strategy_id 前缀 |
| 门店聚集误判 | 接口异常/门店刷单在门店维度聚集 | 缺失率按门店/地市下钻区分故障与欺诈 |
