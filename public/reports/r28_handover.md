## 二、风控策略体系（初审 / 复审 / 捞回）

### 2.1 审批链路
- **前置拦截**：命中硬规则直接拦（典型：「24h 内存在 1 笔授信失败记录」→ 防重复进件）。
  ⚠️ 这类记录**没有 strategy_id**，不是漏配，统计时单列。
- **初审 / 复审**：风控表 `first_risk_result` / `second_risk_result` 分别记录两轮结果。
- **捞回（recall）**：`recall_strategy` 记录捞回机制，初审拦下的部分用户走捞回进复审。
- **拒绝归属**：我方拒绝 = `apply_msg='综合评分不通过'`；英文提示 = 翼支付侧拒绝，**两者分开归因**。

### 2.2 策略分支体系
| 体系 | 说明 |
|------|------|
| 决策树分支 | 江西 `yzf_jx_*`（15 分支）、湖南 `hunan_v1`（23）、贵州 `gz_v1`、通融 `tongrong_v1` |
| 2608 评级体系 | A/B/C/D/E 五档，按省质态分级配额 |
| 分支 = 客群 | 同一分支内客群风险同质，**通过率按分支配置**，不是全省一个数 |

**2608 分级配额规则（参考）**

| 档位 | 质态区间 | 配置通过率 |
|------|------|------|
| A | ≤ 4% | 90% |
| B | (4%, 6%] | 75% |
| C | (6%, 8%] | 50% |
| D | (8%, 10%] | 10% |
| E | > 10% | 2%（缺失分支补此档，避免误杀） |

### 2.3 通过率机制（🔴 关键：pass_ratio 是「分数线」不是概率）
- **综合通过率 = 基础 pass_ratio + 渠道浮动 + 地市浮动 + 套餐浮动 + 代扣浮动**（**五层加法叠加**，不是乘法）。
- **通过阈值 = risk_cutoff[综合通过率] → 换算成模型分（lxf）**；**用户模型分 > 阈值才通过**。
- ⇒ **配置的通过率 ≠ 实际通过率**：实际取决于该分支客群的分值分布与阈值位置，效果**非线性**。
- 不同省即使配同一个数，实际通过率也不同（客群分分布不同）。

### 2.4 调整总原则（双向调控）
- 要**提升** → 优先提**质态优秀**的分支（逾期低、本网、老客）。
- 要**下降** → 优先压**质态较差**的分支（逾期高先砍）。
- 依据**半年质态**分层，不用单日通过率机械反推；幅度克制（单次 +10~20pp），分批执行。

## 三、客群管理

| 维度 | 字段 / 取值 | 风控含义 |
|------|------|------|
| 用户类型 | `custtype`：00 公众 / 01 VIP / 06 存量 VIP | 公众为主力；先享合约仅 VIP |
| 新旧客 | `old_new_customer` 新客户 / 老客户 | 新客风险普遍更高 |
| 运营商 | `operator_real`：**电信 = 本网**，移动 / 联通 = **异网** | 本网质态优于异网 |
| 在网时长 | `online_duration`（**档位码，不是月数**） | 老用户判定 |
| 年龄 / 金额 | `age_interval` / `amt_interval` | 分箱口径 |
| 门店 / 代理商 | `store_id` / `supplier_code` | 归因到渠道 |
| 特殊通道 | 用户白名单 / 保证金白名单 / 特批（`user_risk_level='E'`） | 免风控或放宽，**质态单独看** |

**客群分层（做管控的抓手）**
- **新客 × 异网 × 高直降** = 高危组合，是质态恶化最常见的三层叠加。
- **VIP / 存量 VIP** 单独看，通常走合约类业务。
- 结构变化（新客占比上升、本网占比下降）会让 Vintage 曲线整体抬升，**先排结构、再谈策略**。

> ⚠️ 特批 / 白名单通道**不属于策略分支**，做 Vintage 与质态分析时**必须单列或剔除**，否则曲线被客群结构扭曲。

## 四、套餐管理

- 套餐浮动表 `risk_pack_name_control.pass_ratio`：**加法浮动**（+0.30 = +30 个百分点，不是 ×1.3）。
- 用途：对**特定套餐**（尤其高直降 / 长周期）单独收紧或放松，不牵动全省。
- 重点盯的套餐：**高直降 × 新客** 组合（如四川直降 2880、广西贴息版 36 月）。
- 常见坑：**同名套餐换档**（36 期 vs 36 月）会被漏网，按**主键 + 档位**双重确认。
- 相关浮动层：渠道 `risk_channel_control`、地市 `risk_city_control`，与套餐共同构成五层叠加。
- **资方维度**：同一省份可能分多资方（含保险类），质态与口径要分资方看。

## 五、门店管理

- 体系：**门店（`store_id` / `store_name`）+ 代理商（`supplier_code` / `supplier_name`）**；省份地市以营业厅地址为准。
- **欺诈识别三步**：① 先门店后策略（门店异常先排门店）② 欺诈三特征（集中进件 / 反复提交 / 质态背离）③ 定阈值拉黑。
- **拉黑阈值**：逾期 30 天率 ≥ 10% 触发。
- 管控实例：8/12 拉黑 18 家、8/13 亚速系 12 家。
- 关注点：**拉黑滞后**（`v3_order_store.update_time` ≠ 实际管控时间）、**代理商换手**（门店在代理商间转移）。
- 一句话判断：单店通过率两极分化（要么 100%、要么 0%）+ 反复提交 = 刷单/异常进件信号。

## 六、各省质态管理

### 6.1 质态怎么看
| 指标 | 口径 | 用途 |
|------|------|------|
| 当前逾期率 | `step_num_repay_status=2` 当期未还 | 快速体检 |
| Vintage | 按竣工月 × 账期（mob）逐期未还 | 看真实恶化趋势（**必须剔除特批**） |
| 终损 | 由 Vintage 外推至最终损失 | 资损目标测算 |
| **资损敞口** | **在贷余额 × 终损预估** | 决定**优先动哪个省**，不只看在贷规模 |
| 额度满足率 | 通过单中 `order_amt ≤ credit_amt` 占比 | 路由份额分配依据 |

### 6.2 关键结论（业务级视角）
- 各省差异极大（贵州成熟逾期 11.9% vs 湖南 5.1%），**不能全省一个标准**。
- **敞口排序 ≠ 在贷规模排序**：贵州在贷非最大但敞口第一；湖南在贷最大但终损最低。
- **2026-01 全国风险峰值**；特批放量窗口与三省恶化账期重合 → 跨省同账期透视才能找到系统性共因。
- **成熟度陷阱**：新接入省份最早竣工批次被未表现单稀释，全量口径会低估真实风险。

### 6.3 管控手段（多层组合）
分支档位浮动 + 套餐浮动 + 渠道浮动 + 地市浮动 + 门店拉黑 + 白名单通道管控。

### 6.4 典型处置（示例）
| 省份 | 问题 | 处置 |
|------|------|------|
| 四川 | 高直降 × 新客未还率高 | 18 条分支 −0.5 + 套餐/门店层收紧 |
| 广西 | 本网贡献 85.6%、压量多于提质 | 16 档 −0.60；补换名档漏网 |
| 贵州 | 三档占 79.4%、单分支 46.3% | 24 档 −0.30 |
| 海南 | 保证金白名单通道质态差 | 通道单独评估，需拍板 |

| 链路健康 | 按需 | 路由 / 接口故障窗口要从结论中剔除 |

**监控三条纪律**
1. **先确认线上跑哪套体系**，再谈通过率高低。
2. **通过率必须去重**（按证件号），逐笔口径与去重口径可差 15pp+。
3. **停流期走「停流模式」**：业务停摆 ≠ 单量异常，避免误报。

## 九、配置变更标准流程（勿跳步）

1. `plan.py` 录变更计划
2. 改**本地** `sys_parameter.*` 镜像
3. `config_validate --province <省>` → 必须 **0 错误**
4. `config_push --table <表>` 推送生产
5. **回读校验**：参数值 + `add_time`/`update_time`（**不能有 0000**）+ 行数
6. 变更留批次号，1~2 周后验证实际通过率回落
7. 异常时按批次号**回滚**（改动前先备份原值）

## 十一、难点与注意事项（讲解重点）

1. **口径先行**：通过率必须按证件号去重；金额源单位是**分**；`not (A and B)` 遇 NULL 必须 coalesce。
2. **模拟 ≠ 生产**：模拟分类器与线上分类器可能不同，**调通过率一律以生产实际质态为准**。
3. **先确认线上跑哪套体系**：配置表是 2608、线上可能还在跑 2511（江苏教训，调了没效果）。
4. **cutoff 与 score_control 是两条通道**：cutoff 走专用 API，`config_push` 有黑名单，不要搞混。
5. **外部数据断供**：在网时长 / 在网状态 / 外部评分缺失**不能靠填充救**，需用内部特征重建决策树。
6. **验证要等账期**：通过率 1~3 天可验，质态要等 mob1≈1 月、成熟 ≥6 月。
7. **主键漂移**：门店名 / 代理商名会变，做键用编码不用名称；join 前先查右表主键唯一性。
8. **业务停摆**：停流期数据不代表质态，结论要标注数据窗口。

## 十二、可优化方向（如果重做 / 继续提升）

1. **口径固化**：通过率、Vintage、敞口口径全部写死成工具，杜绝手写 SQL。
2. **监控前置**：门店欺诈、体系切换、档位倒挂从「事后排查」前移到「自动预警」。
3. **变更留痕标准化**：配置变更 → 批次号 → 效果回读，形成闭环台账。
4. **量化模板统一**：每省分析/报告用同一骨架（口径 → 结论 → 证据）。
5. **知识资产化**：案例、方法论、脚本统一入知识库，降低对接成本。
6. **监控体系补强**：把评级的稳定性（PSI）、上线后迭代闭环做成例行巡检。
7. **建模深度**：XGBoost 调参、图算法（团伙欺诈）等方向留待补强。
